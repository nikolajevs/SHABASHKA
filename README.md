# SHABASHKA

Маркетплейс универсальных услуг для Латвии. Заказчики и исполнители находят друг друга и договариваются напрямую. Площадка не принимает оплату за работы; платная подписка отложена.

## Первая версия

- Вход через ChatGPT и регистрация аккаунта с ролью заказчика или исполнителя. Роль можно менять.
- Профиль исполнителя: категория, город Латвии, описание, навыки, стоимость, портфолио в виде HTTPS-ссылок.
- Поиск по тексту, категории и городу.
- Публикация заданий заказчиком.
- Один отклик исполнителя на задание; для отклика нужен заполненный профиль.
- Приватный текстовый чат по отклику, обновление каждые 5 секунд при открытом диалоге.
- Выбор исполнителя заказчиком, отметка выполнения.
- Один отзыв с оценкой 1–5 после выполнения, только от заказчика и только выбранному исполнителю. Рейтинг рассчитывается из отзывов.
- Постоянное хранение аккаунтов, профилей, заданий, откликов, сообщений и отзывов в Cloudflare D1.

Примеры профилей показываются только в пустом каталоге, явно помечены и не принимают отклики. Тестовые записи не включены в миграции и не публикуются.

## Стек и запуск

Node.js 22.13+, React 19, TypeScript, Vinext/Vite, Cloudflare Workers, D1, Drizzle. Интерфейс использует существующие Radix/Shadcn-компоненты.

```sh
npm ci
npm run build
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js d1 execute DB --local --config dist/server/wrangler.json --persist-to .wrangler/state --file drizzle/0000_medical_sumo.sql
npm run dev
```

Миграцию выполняют один раз на пустой локальной базе. Последующие изменения схемы оформляют новыми миграциями. Локальный сайт запускается на http://localhost:5173. Локальная кнопка входа использует тестовый аккаунт Seedy; в опубликованной версии подмены личности нет.

Локальный профиль исполнения хранится в игнорируемом `.sites-runtime/execution-profile.json`; при отсутствии используется portable. Конфигурация логических привязок находится в `.openai/hosting.json`. Реальные ресурсы и защищённый вход опубликованной версии предоставляются Sites.

## Проверки

```sh
npx tsc --noEmit
npm run build
# В отдельном терминале запустить собранный Worker для локального интеграционного теста:
node --import ./scripts/sites-env.mjs ./node_modules/wrangler/bin/wrangler.js dev --config dist/server/wrangler.json --local --persist-to .wrangler/state --ip 127.0.0.1 --port 5174 --inspector-port 0
node scripts/test-market.mjs
```

Интеграционный тест использует доверенные заголовки личности исключительно в локальном собранном Worker: заказчик, исполнитель, посторонний участник. Проверяет роли, географию, безопасные ссылки, закрытость чата, выбор исполнителя, завершение и ограничения отзывов. Выводит префикс созданных тестовых аккаунтов для точечной очистки локальной базы. Не запускается на внешних адресах. Локальный dev-сервер удаляет переданные клиентом заголовки личности.

В production запросы должны проходить через доверенный Sites dispatcher, который устанавливает заголовки личности. Нельзя выставлять Worker напрямую в интернет с доверием к заголовкам пользователя.

## Границы текущей версии

Это основа MVP для проверки сценариев, ещё не публичный коммерческий запуск.

- Текущий вход требует аккаунта ChatGPT. Самостоятельная регистрация через email/пароль или Google не реализована. Для публичного продукта потребуется выбрать и подключить подходящий публичный провайдер входа.
- Портфолио — ссылки; загрузка фотографий и файлов пока отсутствует.
- Интерфейс пока русский. Латышский интерфейс не реализован.
- Не добавлены оплата, комиссии, подписки, споры, продвижение, мобильное приложение и сложная модерация.
- До публичного запуска нужны документы оператора/конфиденциальности, процесс удаления данных, защита от массового спама, эксплуатационное наблюдение и решение о публичном входе. Отказ от обработки платежей сам по себе не определяет юридические обязанности площадки.

## Структура

- `app/page.tsx` — каталог, кабинет и формы.
- `app/api/market/route.ts` — API, проверки ролей и доступа.
- `app/chatgpt-auth.ts` — интеграция идентификации Sites.
- `db/schema.ts`, `drizzle/` — схема и миграции.
- `scripts/test-market.mjs` — локальная проверка полного сценария.
- `docs/PROGRESS.md` — выполненное и следующие этапы.
